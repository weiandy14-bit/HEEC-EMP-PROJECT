## 第二批：頁 A 操作補齊

- 工程師篩選使用有效指派，保留匹配任務的父層；日曆區間採 [from,to)，零工期里程碑保留邊界。
- UI 起訖日以台北純日期輸入，結束日包含當天，API 轉換至翌日 00:00 的排他上界。
- 篩選選單來自有權查看的案件與資源；五大專業讀取全域字典，不寫死名稱。
- 工作明細用 native dialog；Esc 關閉並返回原按鈕，403/404 不洩存在性，載入失敗可重試。
- 兩個新真實 DB 案例覆蓋篩選父子、反向日期、名稱選單、跨案工作 UUID 與無權限負例。
- 時間刻度單元測試覆蓋台北午夜、週一週界與真實月份長度。

## 第三批：P4-A5 大量資料操作

- 甘特改為固定 30px 列高的垂直虛擬捲動；只掛載 viewport + 上下各 8 列。父子遍歷使用迭代堆疊，5,000 層 WBS 不依賴函式遞迴。
- API 每案預設 200 個匹配工作，`task_limit` 1–1,000；`task_cursor` 是 `(sort_key, UUID)` keyset，須同時指定 `project_id`。回傳 `task_next_cursor`、`task_count_remaining`，UI 逐案載入並去重祖先，分頁失敗保留已載資料且可重試。
- 保留完整祖先與接觸已回傳工作的相依邊；深層階層、密集相依仍會增加單頁筆數。API 每頁候選數不是整體回應大小的硬上限。
- 即時 SQL view 不變，沒有新增快取或物化。並行編輯期間 keyset 不提供跨請求快照；排序/篩選變動請重新載入。
- 單元案例覆蓋 50 案×100 工作、單案 5,000 工作、5,000 層階層與精確 spacer；瀏覽器驗證 5,000 工作之 DOM 列數、末列捲動與案件收合。真實 DB 驗證 501 工作三頁、祖先保留與非法游標。
- 尚未取得 50/500 案真實 DB P95、2.5M tasks 壓力與 EXPLAIN 證據；本批不宣稱 G8 效能驗收完成。
